# Skyrim SE 1.7.99 / 1.7.104: what the renderer needed

SkyrimRenderer on 1.7 builds against the MIT CommonLib fork with 1.7 support (`CommonLibVR-ng-mit`, branch
`mit-1.7-ng4.10`: CommonLibVR-ng 4.10.0 plus the 1.7 commit), selected with
`-DSKYRIMRENDERER_COMMONLIB_DIR=<fork>` in its own build folder (`build/release-msvc-mit`). Every 1.7 value
here comes from the two game executables (1.6.1170, decrypted from a running process, and 1.7.104), the Address
Library files and that fork. No GPL CommonLib was read.

Tools: the fork's `tools/ae17` scripts, plus `ripfields.py` (fields of a static object read rip-relative,
compared instruction by instruction in every function with the same ID and shape; the fork's tools normalise
rip-relative operands away, so they cannot see these).

## Changed for 1.7

| What | 1.6.1170 | 1.7.104 | Source | Renderer change |
|---|---|---|---|---|
| `PlayerCharacter` tint masks (`tintMasks`, `overlayTintMasks`) | 0xB18, 0xB30 | 0xB20, 0xB38 | `PlayerCharacter::GetTintMask` (40698) reads 0xB18 / 0xB28 (count) in 1.6 and 0xB20 / 0xB30 in 1.7; the new `BSTEventSink<BSSystemEvent>` base at 0x2D8 (RTTI) | The two hand-written offsets in `ActorPreview.cpp` now go through `GetPlayerRuntimeData()`, which the fork versions for 1.7 (and which gives SE / AE exactly as before) |

The DLL is not an SKSE plugin (consumers load it), so SKSE 2.3's `kVersionIndependentEx_AddressLibraryV5` does
not apply to it; its consumers declare it.
